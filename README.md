# Datheon Student Operating Workspace

This repository contains two connected deliverables:

- **Task 1:** parsers, metadata-preserving chunking, ChromaDB cosine indexing, and an ingestion benchmark.
- **Task 2:** an authenticated multi-tenant RAG API that applies department and access-tier filters before vector search and returns citations from retrieved records.

See [Setup and usage](#setup-and-usage) to run locally. This is a demonstration implementation: configure unique API tokens for local users and use a production identity provider, secret manager, TLS, and persistent database controls before handling real client data.

## Architecture

`datheon/ingestion.py` reads PDF, CSV, and Markdown files using a JSONL metadata manifest. It splits text at paragraph and sentence boundaries with overlap, retaining each source's department, access tier, date, filename, and applicable page/row. Stable chunk IDs make repeated ingestion an upsert. `datheon/vector_store.py` stores vectors in a persistent Chroma collection configured for cosine distance. The default local embedding model is `sentence-transformers/all-MiniLM-L6-v2`; it is downloaded on first use. A deterministic test embedder avoids network/model downloads in tests.

`datheon/api.py` authenticates bearer tokens configured in `DATHEON_API_KEYS`. Each token maps to one department and an explicit allow-list of tiers. `datheon/rag.py` constructs both metadata constraints and submits them to Chroma in the same query as similarity search. The response includes source metadata taken directly from those retrieved records. When `OPENAI_API_KEY` is configured, an OpenAI model generates an answer using only the filtered context; otherwise the API returns a grounded extractive answer. Citations are always built from retrieved metadata, not generated by the model.

## Setup and Usage

Requires Python 3.10 or newer. From the repository root:

```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Set `DATHEON_API_KEYS` in `.env` to a JSON object mapping bearer tokens to user profiles. The example file contains development-only tokens; replace them before use. `OPENAI_API_KEY` is optional. Configure `CHROMA_PATH` and `CHROMA_COLLECTION` to change the local index location/name.

Ingest the included sample data:

```powershell
python -m datheon.cli ingest --data-dir sample-data --manifest sample-data/manifest.jsonl
```

Start the API:

```powershell
uvicorn datheon.api:app --reload
```

Query it with a bearer token:

```powershell
Invoke-RestMethod -Method Post http://127.0.0.1:8000/query `
	-Headers @{ Authorization = 'Bearer junior-finance-demo' } `
	-ContentType 'application/json' `
	-Body '{"question":"What is the expense approval limit?"}'
```

The API also exposes `/health`; interactive API documentation is at `/docs` while running locally. The CLI reports document/chunk counts and elapsed-time throughput. Example filter usage is demonstrated in the automated tests.

## Verification

Run the test suite with:

```powershell
python -m pytest
```

The tests cover all supported file formats, stable metadata/chunk IDs, cosine collection configuration, department/tier filtering, token authentication, and cross-department isolation. They use an in-memory Chroma collection and deterministic embeddings; they do not call an external LLM.

## Benchmark Notes

No throughput number is claimed in this repository because it depends on the machine, corpus, and first-run embedding model download. Run the CLI against the intended corpus to record documents/second and chunks/second on the target environment. The benchmark excludes model download time after the model is cached; run it again with a fresh cache if cold-start latency matters.
